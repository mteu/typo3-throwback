# TYPO3 6.2.31 in your browser

TYPO3 6.2.31, released 2017-04-18, is the last public release of the second
LTS. In your browser, it runs on PHP 5.6.40, compiled to WebAssembly.

[Open TYPO3 6.2.31](../../6.2/){ .md-button .md-button--primary }

| What | Where | Credentials |
| --- | --- | --- |
| Frontend | the site's own page | none |
| Backend | `typo3/` | `admin` / `password` |
| Install Tool | `typo3/install/` | `password` |

The Install Tool's password is the admin's, because 6.2's own installer sets
it so, in Docker too.

The site starts as the Docker stack does. On your first visit, 6.2's own
installer runs in your tab, step by step, and the shell names each step as it
starts. Then the site gets a root page and a plain TypoScript template that
names the release and the PHP it runs on. The root page's title is
"Skaarhøj · Gödöllő · 日本語", stored as UTF-8. The frontend shows it, read
back from the database.

The backend is 6.2's own: one ExtJS page with the module menu, the page tree
and each module beside them. The page tree loads over Ext.Direct, as raw JSON
requests, which reach PHP as they do in Docker.

## What is different from the Docker stack

- **The installer runs in your tab.** In Docker, the entrypoint drives 6.2's
  step installer over HTTP on first boot. Here a twin of that script does the
  same five steps, with the same values and the same checks, and sends each
  request straight to PHP. It takes about 2.6 seconds.
- **The login is rsaauth's, as in Docker.** The login form asks PHP for a
  public key and encrypts your password with it before it is sent. PHP makes
  the key with OpenSSL, compiled to WebAssembly with it. That request takes a
  quarter to half a second, and the login about a second and a half from the
  click to the backend.
- **PHP 5.6.40, as in Docker, with the extensions 6.2.31's Install Tool
  asks for:** fileinfo, filter, gd, hash, json, mysqli, openssl, pcre,
  session, soap, SPL, standard, xml, zip and zlib. It also has ctype,
  tokenizer, Reflection, dom, SimpleXML, libxml and XMLReader. The same PHP
  serves 4.5.40, so it also has the old `mysql` extension, which 6.2's
  Docker image leaves out and 6.2.31 does not use. It lacks mbstring, iconv,
  cURL, PDO, Phar, opcache and the official image's other extensions. 6.2.31
  does without them by default: it converts charsets with its own tables.
- **mysqli's prepared statements are played out in PHP's client library.**
  The database here understands only plain SQL. So the client puts the bound
  values into the statement, escaped, and sends it as one query. 6.2 finds
  your backend session that way, as in Docker.
- **The same `php.ini`.** The site uses the Docker stack's own settings,
  `always_populate_raw_post_data = -1` included, so the page tree's raw
  JSON requests get no deprecation notice in their answers.
- **The clock starts at 2017-04-18 12:00 UTC,** and runs from there.
- **ImageMagick is on, and missing, as in Docker.** 6.2 turns ImageMagick
  on by default, and the Docker image has none. Here, PHP cannot start
  programs at all, and one that is not there answers "not found", as the
  shell does in Docker. So GD draws the images, and what needs ImageMagick
  fails in both places. The Install Tool's ImageMagick tests say they could
  not make their images. Its GD tests draw, and match 6.2.31's reference
  images except for TrueType text: today's FreeType draws slightly different
  pixels than 2017's.
- **TYPO3 moves files with PHP, not with `mv`.** 6.2.31 has that setting for
  Windows servers. Mail goes to `/bin/true`, as in Docker, so it is "sent"
  and goes nowhere. The Install Tool's test mail goes through 6.2's own
  mailer, as in Docker.
- **The database answers as MySQL 5.5.62, in UTF-8,** the server and the
  character set the Docker stack runs. It answers what 4.5 sends, and what
  6.2 adds: the installer's questions about databases and character sets,
  the database analyzer's view of every table, and the caching framework's
  deletes across joined tables. The analyzer finds nothing to change. TYPO3
  sends the same statements to it, and every one of them works.
- **The trusted hosts pattern is open, as in Docker.** PHP is told it runs on
  `localhost`, while your browser asks for the site's real host, so 6.2.31
  would refuse every request. The site sets the pattern to `.*`, as the
  Docker stack's entrypoint does. Only your own tab reaches PHP, so a forged
  host has no one to mislead.
- **No opcache.** Neither stack has one. Here, PHP compiles each script
  again on every request, at close to native speed. A page of the frontend
  takes a few hundred milliseconds.
- **The first visit downloads the whole source,** about 20 MB, and unpacks it
  into the tab's memory: 10,544 files. Once the download is done, the site is
  ready in about four and a half seconds, most of it the installer. A reload
  restores your saved site from the browser's storage in under two seconds.
  With the backend open beside it, the tab uses about 310 MB, some 30 MB more
  than 4.5.40's.

One thing is the same as in Docker, and broken in both: Help > Documentation
throws a JavaScript error as it lists the manuals. 6.2.31's own script there
uses `$`, which 6.2 leaves undefined.
