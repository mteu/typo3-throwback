# TYPO3 3.8.1 in your browser

TYPO3 3.8.1, released 2005-11-14, is the last release before 4.0. In your
browser, it runs on PHP 4.4.9, compiled to WebAssembly.

[Open TYPO3 3.8.1](../../3.8/){ .md-button .md-button--primary }

| What | Where | Credentials |
| --- | --- | --- |
| Frontend | the site's own page | none |
| Backend | `typo3/` | `admin` / `password` |
| Install Tool | `typo3/install/` | `joh316` |

The site starts as the Docker stack does: an admin, a root page, and a plain
TypoScript template that names the release and the PHP it runs on.

## What is different from the Docker stack

- **PHP 4.4.9, not 5.6.40.** Both are PHP that 3.8.1 runs on. It refuses only
  PHP older than 4.1.0 (`typo3/init.php:198`). The Docker stack runs 5.6.40,
  the newest PHP that still has the `mysql` extension 3.8.1 needs. In your
  browser, it runs on the PHP 4.4.9 built for 3.3.0. Every PHP file of 3.8.1
  parses on it, and a 2005 server was as likely to run PHP 4 as PHP 5. So
  the frontend says "Rendered by TypoScript on PHP 4.4.9".
- **The clock starts at 2005-11-14 12:00 UTC,** and runs from there.
- **Images are drawn by GD.** ImageMagick cannot run in a page, so the site
  turns it off, as a 2005 server without it would have. 3.8.1 then limits
  images to GIF, JPEG and PNG itself.
- **The Install Tool skips its ImageMagick tests,** and says why. Its own GD
  tests match the reference images 3.8.1 ships, except TrueType text: today's
  FreeType draws slightly different pixels than 2005's.
- **TYPO3 moves files with PHP, not with `mv`.** 3.8.1 has that setting for
  Windows servers. Here, no program can be started at all.
- **The database answers as MySQL 3.23, not 5.5.** TYPO3 sends the same
  statements to it, and every one of them works. The provisioning script asks
  the server for its connection character set, which MySQL 3.23 does not
  have, and skips that check.
