# TYPO3 4.0.13 in your browser

TYPO3 4.0.13, released 2009-07-02, is the last 4.0 release. In your browser,
it runs on PHP 4.4.9, compiled to WebAssembly.

[Open TYPO3 4.0.13](../../4.0/){ .md-button .md-button--primary }

| What | Where | Credentials |
| --- | --- | --- |
| Frontend | the site's own page | none |
| Backend | `typo3/` | `admin` / `password` |
| Install Tool | `typo3/install/` | `joh316` |

The site starts as the Docker stack does: an admin, a root page, and a plain
TypoScript template that names the release and the PHP it runs on. The root
page's title is "Skaarhøj · Gödöllő · 日本語", stored the way 4.0 stores it:
ISO-8859-1 bytes for what that character set has, character references for
the rest. The frontend shows it, read back from the database.

## What is different from the Docker stack

- **PHP 4.4.9, not 5.6.40.** Both are PHP that 4.0.13 runs on. It refuses only
  PHP older than 4.1.0 (`typo3/init.php:226`). The Docker stack runs 5.6.40,
  the newest PHP that still has the `mysql` extension 4.0.13 needs. In your
  browser, it runs on the PHP 4.4.9 built for 3.3.0. Nine PHP files of 4.0.13
  do not parse on it: PHP 5 code in the bundled ADOdb, which 4.0 loads only
  on PHP 5. So the frontend says "Rendered by TypoScript on PHP 4.4.9".
- **4.0 brings its own `clone()` for PHP 4.** 4.0 copies objects with
  `clone`, a PHP 5 keyword. On PHP 4, `t3lib/compat_php5.php` defines a
  function of that name, and 4.0 loads it only below PHP 5. A page that takes
  its content from another page, with "Show content from page", runs it. The
  Docker stack never does.
- **The clock starts at 2009-07-02 12:00 UTC,** and runs from there.
- **Images are drawn by GD.** ImageMagick cannot run in a page, so the site
  turns it off, as a 2009 server without it would have. 4.0.13 then limits
  images to GIF, JPEG and PNG itself.
- **The Install Tool skips its ImageMagick tests,** and says why. Its own GD
  tests match the reference images 4.0.13 ships, except TrueType text: today's
  FreeType draws slightly different pixels than 2009's.
- **TYPO3 moves files with PHP, not with `mv`.** 4.0.13 has that setting for
  Windows servers. Here, PHP can start one program only: `/bin/true`. The
  Docker stack sends mail to it, so mail is "sent" and goes nowhere, here as
  there.
- **The database answers as MySQL 5.5.62,** the server the Docker stack runs.
  The provisioning script asks it for its character sets, and for the
  character set of a column in `information_schema`. It answers those, all
  `latin1`, and `HEX()` of a string's bytes. Everything else answers as for
  3.3.0 and 3.8.1. TYPO3 sends the same statements to it, and every one of
  them works.
- **`default_charset` does not reach `htmlspecialchars()`.** On PHP 5.6, 4.0's
  record editor needs `default_charset` set to ISO-8859-1, or it shows a
  title with a latin1 character as empty. PHP 4 escapes as ISO-8859-1
  whatever that setting says. The site sets it all the same, as the Docker
  stack does.
